# Pre-merge remediation plan

## Goal and delivery

Deliver a reviewable release candidate that closes the eight security findings, two additional correctness defects and two operating limitations identified at `35f4c484084e74d206d311affc311a593c0d1583`. The reviewed branch is `docs/release-process` and its parent is `99eeaa69abc3f0fa65d18752fd82f3de6f0967fd`. Refresh both branches before implementation and credit any fixes already present when their regression checks pass. [Reviewed revision](https://github.com/knightfall/scaleset-dotnet-aws/commit/35f4c484084e74d206d311affc311a593c0d1583)

Use the existing T01–T26 implementation chat and repository PR workflow. Start with release integrity. The runner, capacity, EC2 and telemetry packages below can proceed independently. Combine their changes on a candidate based on the release branch and run the final checks there. Keep the final merge to `main` for maintainer review. Scope includes implementation, PRs, CI and local qualification. Production deployment, publication and live credentialed canaries are separate operator actions.

## 2. Isolate runner-controlled inputs

4. **Bound the HELLO write at the authorization boundary.** Remove direct runner HELLO writes to the composite-key lifecycle table. Preserve narrowly scoped OFFER consumption and any separately qualified EC2 supervisor STATUS grant. Prefer a dedicated HELLO store keyed only by the AWS-derived principal if the design can enforce bounded records, trusted expiry or cleanup, and bounded write consumption. Otherwise mediate the write through a narrow, authenticated operation that enforces the key, schema, maximum size, expiry and write budget. Preserve the exact-HELLO condition on JIT staging, principal-specific one-time OFFER consumption, lease fences and EC2/Fargate role separation. Design the rollout for retained tables, old task definitions, in-flight handoffs and rollback. **Acceptance:** policy and integration checks cover own and foreign principals, cardinality, cleanup, retries, forbidden lifecycle/index writes, and recovery across the cutover. Test the effective authorization design as well as the cooperative client. [IAM grants](../cdk/lib/infrastructure/runner-iam.ts) · [JIT transactions](../src/Knightfall.ScaleSet.Aws.DynamoDb/DynamoDbLifecycleStore.JitHandoffs.cs)
5. **Contain invalid HELLO records.** Convert invalid runner-authored data into a held or rejected handoff at the decoder boundary. Preserve visibility of controller-owned state corruption. **Acceptance:** a malformed first handshake receives no JIT offer. A second healthy profile completes its handoff on the same worker, including after restart with the bad record retained. Diagnostics expose no payload or credentials.
6. **Validate the Fargate health-check command.** Reject runner task definitions with a configured ECS health check unless every executable argument has an explicit approval contract. Apply the same rule to inspection and dispatch. **Acceptance:** a benign unapproved health check is rejected at both paths, the approved bootstrap still launches, and the controller's own health checks still work. [Fargate preflight](../src/Knightfall.ScaleSet.Aws.Providers.Fargate/FargateProfileInspector.cs)

## 3. Correct Fargate capacity and sustain it over time

7. **Separate foreign tasks from profile occupancy.** Use the same ownership classification in active reconciliation and dry-run planning. A task positively identified as belonging elsewhere consumes applicable physical headroom. Only owned or plausibly owned tasks count against the profile maximum. Preserve conservative handling for ambiguous identity. **Acceptance:** two differently labelled profiles capped at one, sharing a cluster with the controller and an unrelated service, can each launch their first runner when physical headroom permits. Zero headroom still blocks both. [Active backend](../src/Knightfall.ScaleSet.Aws.Controller/Runtime/FargateRunnerBackend.cs) · [Planner](../src/Knightfall.ScaleSet.Aws.Core/Planning/CapacityPlanner.cs)
8. **Make positive idle reserve converge.** Use trusted allocation or registration evidence to credit a warm allocation against its reserve independently of whether it can be advertised as ready for a job. Preserve the configured positive-reserve feature and the ban on workflow-writable Fargate STATUS. **Acceptance:** with zero demand, reserve one and maximum 24, repeated reconciliations across pending, running, registration, idle and controller restart settle at one runner. A terminal task can be replaced once, demand still scales within limits, and ambiguity never advertises false readiness. [Executor classifier](../src/Knightfall.ScaleSet.Aws.Core/Lifecycle/ExecutorClassifier.cs)
9. **Refresh quota evidence without redeployment.** Replace the startup-only active quota observation with a refreshable, trusted account-and-region source. Retain the existing age limit, expiry and distinction between zero and unknown. Account for other workloads, reservations and subnet headroom. Use read-only permissions for the chosen source and a bounded, cancellable refresh. **Acceptance:** a deterministic test runs beyond ten minutes, holds new starts when evidence expires or reads fail, and resumes on genuinely fresh evidence without restarting. Another profile cannot spend the same headroom twice. Document target qualification for the source and preserve existing deployment input compatibility. [Runtime evidence](../src/Knightfall.ScaleSet.Aws.Controller/Configuration/FargateRuntimeEvidence.cs) · [Profile bindings](profile-bindings.md)

## 4. Restore EC2 replacement and make cleanup operable

10. **Recover externally terminated instances.** Reuse the existing terminal-observation rule in periodic inventory and event reconciliation. A positive EC2 terminal readback can be corroborated with the persisted instance ARN, allocation, incarnation, ownership and numeric launch-template provenance after its primary network interface detaches. **Acceptance:** external termination retires exactly the matching durable executor and permits replacement, including across restart or duplicate events. Missing resources, events alone and mismatched claims keep capacity held. [EC2 backend](../src/Knightfall.ScaleSet.Aws.Controller/Runtime/Ec2RunnerBackend.cs) · [Existing terminal readback](../src/Knightfall.ScaleSet.Aws.Providers.Ec2/Ec2EffectProvider.Observation.cs)
11. **Make the EC2 cleanup mode explicit and testable.** Preserve the safe default. Supply a supported opt-in path binding qualified AMI/launch-template evidence to the supervisor-only STATUS grant and bootstrap configuration. Expose the default mode's external reclamation requirement during configuration or preflight and in the runbook. **Acceptance:** the emulated qualified path reclaims only after authenticated process exit, GitHub completion and the existing grace period. The default or unqualified path holds a still-running host and reports why. Fargate never receives STATUS authority. Keep real AMI/IMDS qualification operator-owned. [EC2 bootstrap](ec2-runner-bootstrap.md) · [Profile qualification](profile-bindings.md)

## 5. Protect telemetry credentials

12. **Require TLS for credential-bearing remote OTLP.** Check the effective destination and headers after global settings, signal-specific overrides and inherited headers resolve. Preserve the local loopback smoke path. **Acceptance:** across supported signals and transports, remote HTTP with inherited or direct credentials is rejected before a send. Remote HTTPS and the permitted loopback configurations succeed. Neither validation errors nor logs reveal header values.
